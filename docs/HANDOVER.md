## 1. この企画は何か

KUN の「50人クラフト」向け企画。5勢力が中央の石油を奪い合い、
時代を進めていく。**判定と記録はシステム、承認と裁定は人間**が持つ。

### 役割分担（重要）

| | 持つもの | 場所 |
|---|---|---|
| **データパック（このフォルダ）** | **状態と判定** | `datapacks/jidai_craft/` |
| プラグイン（別チャット） | **操作画面（GUI・コマンド）** | `plugin/` |

**境界はスコアボードの名前。** [datapacks/CONTRACT.md](datapacks/CONTRACT.md) が正本
（[SCOREBOARD.md](SCOREBOARD.md) は解説版）。
名前を変えたら**必ず両方のチャットで合わせる**（過去に1度ズレて勢力購入が全滅した）。

### 作成者について

- **コマンドを勉強中。** 読めない実装は失敗とみなす
- 全関数の冒頭に日本語コメント。複雑な行にも説明を付ける
- **動くことより読めることを優先**（初回指示書からの一貫した方針）

## 3. 動かし方

1. ワールドの `datapacks/` へ `jidai_craft` をコピーして `/reload`
2. `/function jidai:setup/kyoten` — 5拠点と中央に施設を置く
3. `/function jidai:setup/tetsu` — 全員に鉄装備を配る
4. `/tag <名前> add jidai_unei` — 運営に進行通知が届くようにする

撤去は `/function jidai:uninstall`。

## 4. 確定していること（勝手に変えない）

| 項目 | 値 | 経緯 |
|---|---|---|
| マップサイズ | **1500版** | 実機計測 58秒で適正と判断 |
| 拠点半径 | **r=410** | 比例拡大(469)より控えめ。往復が企画を食わない |
| 時代 | **4段階**（鉄器→中世→近代→現代） | 石器は廃止。開始時に鉄装備配布 |
| 進行条件 | 石油20% / 貯金 / 建築 の3つ | 承認は人間 |
| 中央の時代 | 2勢力到達で上がる | 銃の解禁もこれで判定 |
| 徴収 | 4割・端数切り捨て | ログアウトで逃げられない（世代方式） |
| 傭兵の識別 | `youhei` スコア（1=傭兵） | **運営がOPコマンドで指定**。契約では触らない |
| 傭兵の売却 | **禁止** | 石油の価値を保つため。掘る・持つ・渡すは自由 |
| 石油の紛失 | スコアなので失わない | 引き出した分だけが危険 |
| 死亡時 | 引き出した石油は**落とす** | 作成者の回答（2026-08-18） |
| **先行の定義** | **勢力の時代 > 中央の時代** | 作成者の回答（2026-08-18） |
| **先行の対象数** | **常に1勢力**（独走している勢力だけ） | 中央が2勢力到達で即上がるため。指示書の「2勢力」は成立しない。**確認済み** |
| **保有量の公開** | **ペナルティから削除** | 通常時から常時公開なので、先行時との差が無い（指示書§3-1 の推奨どおり） |
| **位置公開の手段** | **発光（`glowing`）** | チームの色で光るので勢力も同時に分かる。数字を読ませない |
| **採取コスト増** | **案A（拾っても一定確率で1本にならない）** | 対象は**中央プラント産の石油だけ**。取引で得た石油は目減りしない |
| **腐敗の判定単位** | **勢力単位**（傭兵は1人=1単位） | 仲間内で渡し合っても総量は変わらないので回避できない |
| **腐敗の減り方** | **割合・切り上げ** | 勢力50〜100本 / 傭兵数本と規模が違う。切り捨てだと小分けで逃げられる |
| **腐敗の時計を戻す条件** | 減り幅が**腐敗で取られる量以上**の時だけ | 1本だけ払って無限に逃げるのを防ぐ。作成者の回答（2026-08-18） |
| **宣戦の入口** | **プラグインが `sensou/sensen` を呼ぶ** | 中央のエメラルド→販売所GUI→戦争宣誓→相手選択。作成者の回答（2026-08-18） |
| **戦争の持ち方** | 2勢力の関係。**両方向に同じ状態を書く** | どちらから読んでも1行で分かる。略奪は双方向なので片方だけだと反撃できない |
| **今ある戦争の一覧** | **マーカー1体＝戦争1つ** | バニラに保持者を並べる方法が無い。勢力が増えても時計側は無変更 |
| **略奪の石油** | **相手勢力で最も多く持つ個人 → 押した本人** | 石油は個人スコア。勢力合計は毎秒作り直される派生値なので引けない。作成者の回答 |
| **占領の記録** | `senryou` に**占領している勢力の番号** | スコアは整数しか持てない。番号→名前は1行ずつ引く |
| **占領の解除** | **下剋上の行使だけ**（時間では解けない） | 作成者の回答（2026-08-18） |
| **占領の成立条件** | 貯金0 **かつ 相手が一度は略奪している** | これが無いと、時代進行で貯金を使った直後に無傷の相手から占領される。最も前進した勢力が最も惨めになるので「殴った者だけが取れる」形にした |
| **下剋上** | 販売所の商品・勢力の金150・近代解禁・1つまで | 買うのは誰でも／使うのはリーダーかつ占領中のみ。作成者の回答 |
| **下剋上の解禁時代** | **中央の時代**で見る | 勢力の時代だと、遅れている（＝占領されがちな）側ほど買えなくなる |
| **傭兵のチーム** | **未雇用だけ `youhei` チーム** | 常に隔離すると PvP の味方判定が壊れる。分離は `youhei` スコアで行う。作成者の回答 |

## 5. 実測で分かった罠（再発防止）

**すべて実際に踏んで直したもの。** 詳細は README の第3部と `map/README_paint.md`。

### Minecraft 1.21.10

| 罠 | 正しい形 |
|---|---|
| **ダミープレイヤー名に引用符** | `"丘陵"` は引用符ごと別の保持者になる。**引用符なし** |
| `mine_block` トリガは**存在しない** | ブロックを掘った検知は無い。目印アイテム経由にする |
| 本人特定 | `default_block_use`（ボタン・容器で発火。押した本人が確定） |
| アドバンスメントの**未知フィールドは黙って無視** | 打ち間違えると条件なしで発火する。実測で確かめる |
| 範囲内のブロックを数える命令が**無い** | `clone ... filtered` が個数を返す（非破壊・上限32768） |
| `fill ... replace` で同じブロック | 「0個」と返る。数えるのに使えない |
| アイテムが消える・燃える | `Age:-32768` と `Invulnerable:1b` |
| `give` の個数が可変 | その場に書いた数字しか通らない → マクロが要る |
| `clear @s <item> 0` | 1個も消さずに**個数だけ返す**（数えるのに使う） |
| 0人のとき `@a` に直接コマンド | 赤字が出る。`execute as @a run` を通す |
| `schedule` に `replace` 無し | `/reload` のたびに時計が増える |
| 調整できる確率が書けない | **`random value 1..100` がある**（1.20.2+）。`execute store result` でスコアに入る |
| 設定の初期化に `matches 1..` | **0 を設定すると `/reload` で既定値に戻る**。0 が意味を持つ設定は `matches 0..` で書く |
| `effect give` の重ねがけ | `infinite` で毎秒かけ直しても**効果は1つのまま**（実測）。復帰時の付け直しに使える |
| 効果はログアウトで消えない | 消す相手を**タグで覚えておかないと消し忘れる**（`jidai_hikari`） |
| `custom_data~{a,b}` の複数キー | **含んでいれば一致**。2キー指定で「中央産だけ」を狙い撃てる（実測） |
| 最大値・最小値を求める命令 | `scoreboard players operation A obj > B obj` が最大、`<` が最小 |
| 割り算の切り上げ | `(a*率 + 99) / 100`。切り捨てだと少量が 0 になり抜け穴になる |
| **`execute if data storage` の書き方** | `jidai:kari{k:""}` は**落ちる**。id とパスの間に**スペースが要る**（`jidai:kari {k:""}`） |
| マクロの引数忘れ | **`Failed to instantiate function` で止まる**。黙って通らないので打ち間違いに気づける |
| マクロに引数を直書き | `function ns:f {a:"丘陵"}` が使える。**運営が手で打てる**形になる |
| **`summon` 直後の `@e` は取りこぼす** | チャンクの読み込みが間に合わないと拾えない。**タグは summon と同時に付ける**（実測で拠点2だけ印が付かなかった） |
| 近い施設を `distance=..N` で見分ける | **重なって後の行が勝つ**。`sort=nearest,limit=1` で1体に絞る |
| `execute as @e[...]` の中 | `@s` がその相手に変わるので**本人のスコアが読めない**。目印を置いて後で置き換える |
| サイドバーに数字を2つ出したい | `scoreboard players display name` で表示名に書き込み、`numberformat blank` で右の数字を消す |
| サイドバーの並び順 | スコアの**大きい順**。上に固定したい行は大きな下駄をはかせる |
| 「チームに入っていない人」の選び方 | `@a[team=]`（値なし）で選べる |
| 保持者名に記号 | `丘陵>森林` のような名前が使える。組み合わせの状態を持たせられる |

### 検証のやり方

- **「塗った」で満足せず Export して数える。** 鉱石はこれで発覚した
- **対照実験を必ず入れる。** 「効いている」のか「たまたま」なのかを区別できる
- **straight（直線）で測ると過小評価する。** 歩ける判定は塗り広げ（幅優先探索）で測る
- プレイヤーが要る処理は、**チームに入れたアーマースタンド**で代用できる
- 時間のかかる検証は `/tick sprint <ticks>` で早送りできる
- **検証サーバーの世界を消し損ねると、数字がぜんぶ二重になる。**
  前回のアーマースタンドとスコアが生き残るため。
  `shutil.rmtree(..., ignore_errors=True)` で握りつぶしていたので、
  「傭兵1人のはずが2人」「金30のはずが60」「111が222」という
  原因の分からない失敗が12件出た。**消せなければその場で止める**ように直した
  （前の `java.exe` が掴んでいることがある）
- **失敗した数字が「きれいに2倍」なら、まず世界の消し忘れを疑う。**
  ロジックを読み直す前にこれを見た方が早い
- **`@p` は検証サーバーでは誰にも当たらない**（プレイヤーが1人も居ないため）。
  黙って何もしないので、テストが通ったように見えてしまう。必ず `@e[tag=...]` を使う

## 6. 自分がやったことで、後から効きそうな判断

- **暫定UIは消さない。** プラグインが完成したら**マーカーを置かないだけ**で無効化できる形にした
- **設定値は `settei` スコアに逃がした。** 運営もプラグインも書き換えられる。`/reload` で消えない
- **勢力を増やす場所にはコメントを打ってある**（`勢力を増やす時は、ここに1行足す`）。
  **5勢力化は済んでいる**（丘陵・森林・川・内海・岩場）。もし6つめを足すなら、触るのは
  **書き足す14箇所 + 複製する3ファイル**。

  | 書き足す | `load`（初期値6行・表示3行）/ `clock`（集計2行・番号1行）/ `kinko_yomu` / `kinko_kaku` / `junban` / `chuo` / `senkou/hantei`（判定5行・発光1行）/ `sekiyu/hirotta`（1行）/ `fuhai/hantei`（1行）/ `sensou/kuni_yomu`（1行）/ `sensou/aite_yomu`（2行）/ `sensou/gekokujo_kau`（1行）/ `sensou/gekokujo_tsukau`（5行）/ `hyouji/kousin`（5行）/ `setup/kyoten`（mitei をチーム名に） |
  |---|---|
  | 複製する | `shinko/hantei_<勢力>` / `shinko/shounin_<勢力>` / `fuhai/<勢力>` |

  複製する3つは、どれも**勢力名とチーム名を書き換えるだけ**で済む形にしてある。
  **戦争の時計と略奪の本体は、勢力が増えても1行も変えなくてよい**
  （戦争はマーカーで数え、相手の指定は勢力名ではなく番号で書いてあるため）。
- **関数は31→54個で、初回指示書の「15個以内」を超えている。**
  機能量的に守れなくなったので、フォルダ（`kane/` `sekiyu/` `shinko/` `mise/` `setup/` `senkou/` `fuhai/` `sensou/` `hyouji/`）で分けた
- **戦争を「エンティティ」で持った。** バニラに「スコアの保持者を並べる」方法が
  無いので、戦争1つにつきマーカーを1体置いている。**マーカーが消えた時が戦争の終わり。**
  勢力が5つに増えても、時計は `@e[tag=jidai_sensou]` を回すだけで変わらない
- **「相手勢力の人」を勢力名ではなく番号(`bangou`)で選ぶようにした。**
  番号なら `if score @s bangou = #aite_no` の1行で書けるので、
  略奪の本体をマクロにしなくて済む（読みやすさとスケールの両取り）
- **上限の計算を `sensou/ryakudatsu_ryo` に切り出した。**
  `senkou/loss` と同じ理由。切り出したので、検証が
  「金は10回・石油は5回で打ち止め」を**実際に数えて**確かめられる
- **確率の計算だけを `senkou/loss` に切り出した。** 拾得処理の中に埋めると
  実プレイヤーが要って測れない。1関数にしたので、検証が**200回呼んで割合を数えられる**
- **腐敗の判定は `fuhai/kyotsu` に集約した。** 勢力も傭兵も同じ関数を通る。
  入出力が `#gokei` `#kijun` `#byou` `#yuyo` → `#heru` だけなので、**机上の値で全パターン試せる**
- **先行の設定は `matches 0..` で初期化した**（既存は `matches 1..`）。
  0 が「ペナルティ無し」という意味を持つため。既存の設定にはこの問題が残っている
