# 指示: 世界の時代バー（ボスバー）の絵を作る

Minecraft のイベント「時代クラフト」で、画面の上に出す**進捗バー**の絵を作ってください。
既にあるUI（販売所・銀行・ガチャ）と同じ**古地図風**で揃えます。

作業場所は、この企画の置き場の直下（`README.md` がある所）です。

> この指示は Codex 向けの依頼文 `docs/Codex依頼文_ボスバー.md`
> （sha256 `8c00089c7743cafad7bf2c4a2a57d10447acf431ab68f88c690ba457452c046f`）
> を、Claude Code で作る前提に書き直した物です。**こちらが新しい方**です。
> 変えた所は §9 にまとめてあります。

## 1. 何のバーか

参加者60〜70人が5つの勢力に分かれ、鉄器時代から未来を目指します。
このバーは**世界全体が次の時代にどれだけ近いか**を示します。

- **2つの勢力が次の時代の条件を満たすと、世界の時代が上がります**
- バーはその進み具合で伸び、時代が上がると**空に戻ります**
- 満タンは `6`（2勢力 × 3条件）。**動きは7段階**（0〜6）

数字は出しません。**バーの伸びと色だけで、視聴者に世界の状態が伝わる**のが狙いです。

## 2. 作る画像

### `bar_frame.png` ── 枠（空の状態）

| | |
|---|---|
| 大きさ | **728 × 32 px** |
| 内訳 | 中身が入る「溝」が 720 × 24 px。**上下左右すべて 4px の縁** |
| 背景 | 透過（PNG・アルファ付き） |

バニラのボスバーは 182×5px しかありません。**横はちょうど4倍**（182×4 = 728）で作り、
クライアントMODが縮小せずそのまま描きます。溝の 720px は 180 論理px にあたります。

時代の名前（「世界の時代　近代」）は**バーの上にMinecraftが実行時に描きます**。
枠の中に文字を焼き込まないでください。

### `bar_fill_<時代>.png` ── 中身（4枚）

| ファイル | 時代 | バニラの色 | 色の方向 | 手持ちの色 |
|---|---|---|---|---|
| `bar_fill_tekki.png` | 鉄器 | `white` | くすんだ灰白 | `#AEB8AE` |
| `bar_fill_chusei.png` | 中世 | `yellow` | 真鍮・古びた金 | `#C4934B` |
| `bar_fill_kindai.png` | 近代 | `blue` | 青緑 | `#4FA1B2` |
| `bar_fill_gendai.png` | 現代 | `purple` | 明るい薄紫 | `#B9A7D0` |

どれも **720 × 24 px**。**同じ形・同じ大きさで、色だけ違う4枚**にしてください。

「バニラの色」の列は、データパックが `bossbar set jidai:chuo color ...` で送る値です。
クライアントMODはこの色を見てどの絵を使うか決めます。**対応を勝手に入れ替えないでください。**

★ `#B9A7D0`（現代）**だけは既存パレットに無い新色**です。ここは足します。
　 他の3色は `manifest.json` の `palette` にある物をそのまま使ってください
　 （`muted` / `brass` / `info`）。

## 3. 中身の切り方（ここを外すと作り直しになります）

**左端から `幅 × 進捗` だけ切り出して描きます。**
中央から広がる、両端から詰まる、といった作りにはしないでください。

切る位置は7つしかありません。

```
0 / 120 / 240 / 360 / 480 / 600 / 720 px
```

720 ÷ 6 = 120 なので、**どの段階も 120px ちょうどの境目**で切れます。
横方向に模様を入れるなら、**120px の倍数で繰り返す**形にしてください。
そうすれば切れ目が模様の途中に来ません。

**縦方向は場所によらず一様に**してください。上下のグラデーションは構いませんが、
横に進むほど模様が変わる作りにすると、切った時に不自然になります。

## 4. 色と作りの決まり

### 色の正本

`manifest.json` の `palette` が正本です。勝手に変えないでください。

| 役割 | 色 | どこに使うか |
|---|---|---|
| `outer` | `#102329` | いちばん外側 |
| `panel` | `#685E45` | 枠の本体 |
| `light` | `#B2A577` | 枠の上と左のハイライト |
| `dark` | `#1B282B` | 枠の下と右の影 |
| `slot` | `#38474A` | 中身が入る前の空の溝 |

### 古地図風とは（このUIでの決まり）

- **羊皮紙のような、少しくすんだ色**。彩度は高くしない
- **1px の硬い縁取り**。ぼかさない
- **紙の繊維のような細かいノイズ**を薄く乗せる。ただし切っても不自然にならない程度に
- **斜めのハッチングは使わない**（横に切ると縞がずれて見える）
- 角は**直角**。丸めない

### 既存の絵が全部守っている決まり（`manifest.json` の `qa` より）

- アンチエイリアスを掛けない。**中間色を作らない**
- アルファは **0 か 255 だけ**。半透明を作らない
- **完全に透明な画素の RGB は `0,0,0`** にする
- 1枚あたりの色数を抑える。**このバーは32色以内**

配信で見るので、**4色は明度でも差を付けて**ください。色相だけで分けると、
配信の圧縮とMinecraftの明るさ設定で潰れて区別が付かなくなります。

## 5. どう作るか（★Codex版と一番違う所）

**手で描かないでください。絵を吐くスクリプトを書いてください。**

既存のUIも同じ作り方です（`manifest.json` の `provenance` に
`deterministic raster construction from a fixed palette, integer rectangles,
one-pixel lines, repeated stamps and mirrored coordinates` と書いてあります）。

| | |
|---|---|
| 置き場所 | `clientmod/tools/bar_tsukuru.py` |
| 吐き先 | `clientmod/ui/assets/jidaiui/textures/gui/` |
| 動かし方 | `python clientmod/tools/bar_tsukuru.py` |

守ること。

- **2回動かしたら同じ byte が出る**こと。乱数を使うなら種を固定する
- **フォントを読み込まない。文字を描かない**（名前はMinecraft側が実行時に描く）
- 色は `manifest.json` から読む。**スクリプトに16進を直書きしない**
  （`#B9A7D0` だけは新色なので、スクリプトの先頭で1か所にまとめて定義する）

## 6. 自分で検査する

`tests/bar_kakunin.py` を書いて、動かして、**結果の数字をそのまま報告**してください。
このプロジェクトの他の検査（`tests/*_kakunin.py`）と同じ形にしてください
── `[PASS] 名前` / `[FAIL] 名前  理由` を1行ずつ出し、最後に件数を出します。

見る物。

1. 5枚の大きさが指定どおりか（枠 728×32、中身 720×24 が4枚）
2. 1枚あたりの色数が32色以内か
3. アンチエイリアスの中間色が入っていないか（アルファが 0 か 255 だけか）
4. 完全に透明な画素の RGB が `0,0,0` か
5. 4枚の `bar_fill_*` が**形は同じで色だけ違う**か（アルファの形が完全一致するか）
6. 4枚の色が**明度でも離れている**か
7. 0/120/240/360/480/600/720 のどこで切っても、縁が破綻しないか
8. 枠の縁が上下左右とも 4px か
9. 使っている色が `manifest.json` の `palette` にあるか（新色 `#B9A7D0` を除く）
10. スクリプトを2回動かして byte が一致するか

★ **書いた検査は、わざと壊して落ちることを確認してください。**
　 このプロジェクトの流儀です。通ることを確かめただけでは、
　 検査が実は何も見ていない場合に気付けません。
　 確認したら**必ず元に戻して**、もう一度通してください。

## 7. manifest.json に足す

`manifest.json` の `files` は48件あり、**画面の正本**になっています。
ここに載っていない絵は「無い物」として扱われます。5件足してください。

形は既存の項目に合わせます。

```json
{
  "file": "assets/jidaiui/textures/gui/bar_frame.png",
  "resource_location": "jidaiui:textures/gui/bar_frame.png",
  "purpose": "世界の時代バーの枠（空の状態）",
  "category": "bossbar",
  "dimensions": [728, 32],
  "blank_regions": []
}
```

**プレビューは本番の画像を最近傍で拡大した物にしてください。** 別に描き起こさないでください。
`bar_tsukuru.py` が同じ実行の中で吐けば、ずれようがありません。

`BOSSBAR_SPEC.md` には、**この指示文の sha256** を書いてください。
どの版の指示で作ったかが分からないと、直しの往復が増えます。


## 10. Codex版から変えた所

| | Codex版 | こちら | なぜ |
|---|---|---|---|
| 枠の高さ | 728 × **40** | 728 × **32** | 40 だと上下の縁が 8px になり、「縁は4px」と合わなかった |
| `bar_fill.png` | 満タンの見本として別に要求 | **やめた** | 時代ごとの4枚と中身が同じで、正本が2つになる |
| 切る位置 | 「左から」とだけ | **7か所を明記**（120px刻み） | 模様を入れる時、どこで切れるか分からないと作れない |
| 作り方 | 指定なし | **スクリプトで吐く** | 直しが効き、2回目も同じ物が出る |
| 検査 | こちらで機械にかける | **そちらで書いて動かす** | 落ちた状態で納品されるのを防ぐ |
| 色の出所 | 表に16進を並べた | **manifest.json から読む** | 表と実物がずれる |
| 明度 | 指定なし | **4色は明度でも離す** | 配信の圧縮で色相だけだと潰れる |
| 納品先 | `nouhin/bossbar/` | **本番の場所へ直接** | 決定的に作り直せるので、隔離する意味が無い |
