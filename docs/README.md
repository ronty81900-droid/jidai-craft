# 第1部 データパック `jidai_craft` v6

## 1. 導入と初期設定

1. ワールドの `datapacks/` へ `jidai_craft` をコピーして `/reload`
2. 施設を置く: `/function jidai:setup/kyoten`
3. 開始時に装備を配る: `/function jidai:setup/tetsu`
4. 運営に通知を受け取るタグを付ける: `/tag <名前> add jidai_unei`

**撤去**: `/function jidai:uninstall`

## 2. 帯ワ層が覚えるのは3つだけ

| ブロック | 用途 | 場所 |
|---|---|---|
| **エメラルドブロック** | 売却所（貴金属を全部売る） | 各拠点。中央では売れない |
| **金ブロック** ×3 | 銀行（10 / 50 / 全部を勢力へ預ける） | 各拠点のみ |
| **ダイヤブロック** | ガチャ | 各拠点（**プラグイン側が実装**） |

**掘る → 拠点へ持ち帰って売る → 預ける。** これだけで完結する。

- 登録した座標のブロックだけが反応する（`default_block_use` で本人特定）
- **壊しても1秒以内に戻り、壊しても何も落ちない**（ルートテーブルを空にした）

### 設置座標（拠点の中心から見た相対位置 / 高さ Y=101）

| 相対 | ブロック | 用途 |
|---|---|---|
| (-6, +6) | 金 | 銀行 10預ける |
| (-3, +6) | 金 | 銀行 50預ける |
| ( 0, +6) | 金 | 銀行 全部預ける |
| (+4, +6) | エメラルド | 売却所 |
| (+7, +6) | ダイヤ | ガチャ（プラグイン） |

**5拠点とも同じ配置。** 拠点の中心（1500版）:
#1 丘陵 (0,-410) / #2 森林 (390,-127) / #3 川 (241,332) / #4 内海 (-241,332) / #5 岩場 (-390,-127)

中央: (0,97,0) 中央プラント（石油の湧き口）/ (0,97,6) エメラルド（買う専用・売れない）

ゲーム内では `/function jidai:setup/zahyou` で同じ表が出る。

## 3. 貴金属 ── 持ち帰って売る

石・花崗岩・閃緑岩・安山岩をピッケルで掘ると **鉄15% / ラピス8% / 金4% / ダイヤ1%**、**深層岩は 1.5倍**（鉄22.5% / ラピス12% / 金6% / ダイヤ1.5%）（データパックのルートテーブル。それぞれ独立に判定）。さらにプラグインが **ネザライト 0.1%（深層岩は 0.2%）**。銀行の単価（鉄1/ラピス5/金10/ダイヤ15/ネザライト30）で1ブロックあたりの期待値は **約1.13円（深層岩 約1.70円）**。正本は `tests/horu_tsukuru.py`。
**爆破では1個も出ない。地中に鉱石は埋まっていない。**

| 段階 | 状態 | 失うか |
|---|---|---|
| 掘る・持ち帰る | アイテム | **失う（死亡・溶岩）** |
| 拠点で売る | 個人の金 | 失わない |
| 銀行へ預ける | 勢力の貯金 | 失わない |

**危険なのは運搬中だけ。** 売らずに持っていれば勢力の貯金に反映されない＝富を隠せる。
これは意図した抜け穴なので塞いでいない。

## 4. 石油

- **スコアで保有。死んでも溶岩でも失わない**
- 中央プラントが **30秒に1本** 地面へ落とす。早い者勝ち
- 拾うとスコアに入り、アイテムは消える（持ち歩けない）
- `/trigger sekiyu_dashi set 5` で **アイテム化**（取引用）。出した分だけが危険
- 落ちた石油は **消えない・燃えない**（実測で確認）
- **プラントの中ではなく、周囲4方向の出口に順番に落ちる**（人が1箇所に固まらない）

## 5. 時代進行（4段階）

鉄器 → 中世 → 近代 → 現代。**石器は廃止**し、開始時に鉄装備を配る。

### 3条件（すべて満たすと運営へ通知）

| | 条件 | 初期値 |
|---|---|---|
| A | 勢力の石油が、その時代の湧出上限の20% | 100本の20% = **20本** |
| B | 勢力の貯金 | **100**（進行時に消費。累積にしない） |
| C | 拠点の判定区画に指定ブロック | **24個以上** |

### 承認

**数えるのはシステム、開けるのは人間。** 3条件が揃うと運営（`jidai_unei` タグ）に通知が出るが、
承認コマンドを打つまで時代は進まない。

```
/function jidai:shinko/shounin_kyuryo
```

承認時にもう一度3条件を確かめるので、条件が崩れていたら通らない。

### 中央の時代とリセット

**2勢力が次の時代へ到達すると中央の時代が上がる。** その時に石油の湧出がリセットされ、
持ち越した石油から **4割を徴収**する（端数切り捨て）。銃の解禁も中央の時代で判定する。

## 6. 先行ペナルティ（v5）

**先行 = 勢力の時代 > 中央の時代。**

中央は「2勢力が到達したら上がる」ので、2つめの勢力が着いた瞬間に中央も上がる。
つまり **`senkou=1` になるのは独走している1勢力だけ**で、全員が追いつけば自動で解除される。
追加の判定基準はいらず、プレイヤーへの説明も「中央より先に行くと目立つ」の1行で済む。

| ペナルティ | 中身 |
|---|---|
| 位置の公開 | 正規メンバー全員が **`glowing` で光る**。チームの色なので、どの勢力かも同時に分かる |
| 採取コスト増 | **中央プラント産の石油**を拾う時、`先行_ロス率`（既定50%）を失う |
| 保有量の公開 | **入れていない**。通常時から常時公開なので、先行時との差が無い |

- **傭兵は対象外**（`youhei=1` は光らないし目減りもしない）
- 発動・解除の両方を全体チャットに出す（黙って光ると理不尽になる）
- 発光は**毎秒かけ直す**ので、ログアウト中に状態が変わった人も復帰1秒後に正しくなる
- 目減りは「2本拾って1本ぶん」。端数は確率で埋めるので、**1本ずつ拾っても回避できない**

**目減りするのは中央プラントが出した石油だけ**（`moto:"chuo"` の印で見分ける）。
引き出して取引した石油には印が無いので、**他勢力から買った石油や
自分で引き出して拾い直した分は目減りしない**。

## 7. 石油の腐敗（v5）

**勢力の石油総量が一定時間 減らなければ、その勢力から減らす。**

| | 既定値 |
|---|---|
| 猶予（勢力） | **900秒**（15分） |
| 猶予（傭兵） | **1800秒**（30分）。持ち高が数本と小さいので長め |
| 減る量 | 総量の **10%・切り上げ** |
| 時計が戻る条件 | 減り幅が **腐敗で取られる量以上**（既定10%） |

- **判定は勢力単位。** 仲間内で渡し合っても総量は変わらないので回避できない。
  他勢力へ売れば本当に減るので、正しく回避できる
- 減るのは **その勢力で最も多く持っている個人**から。溜め込んだ本人が罰を受ける
- **引き出して手に持っている石油も総量に数える**。数えないと、腐る直前に
  全部引き出して逃げられる
- **傭兵も腐る。** 腐らせないと、勢力が傭兵に預けて時間を稼げてしまう（最強の貯蔵庫になる）
- 割合・切り上げにしたのは、切り捨てだと少量が0本になり
  「傭兵に小分けして預ければ腐らない」抜け穴が復活するため

### 時計が戻る条件に下限を置いた理由

「1本でも減れば戻る」にすると、**傭兵に1本払うだけで腐敗を無限に回避できる**。
腐敗で持っていかれる量以上を使った時だけ「使った」と認めることで、逃げても得にならない。

`腐敗_必要減少率` を `腐敗_減少率` と同じ値にしてあるので、
**「腐敗で取られるより多く使えば腐らない」の1行で説明できる。**
指示書どおりの素直な形にしたければ `腐敗_必要減少率` を `1` にする。

## 8. 戦争・略奪・占領（v6）

### 8-1. 戦争の状態

**2勢力の関係として持つ。** 3勢力以上が同時に交戦していてもよい。

| 状態 | 長さ | 略奪 |
|---|---|---|
| 準備 | **5分** | できない |
| 交戦 | **10分** | **できる** |
| 再戦禁止 | **30分** | できない。同じ組み合わせで宣戦もできない |

宣戦はプラグインが呼ぶ。
**中央のエメラルドを押す → 販売所GUI →「戦争宣誓」→ 相手を選ぶ → 関数を呼ぶ。**

```
function jidai:sensou/sensen {kuni:"丘陵",aite:"森林",soku:0}
```

**今ある戦争はマーカー1体で1つ。** バニラには「スコアの保持者を並べる」方法が
無いので、戦争の一覧をエンティティで持っている。時計はマーカーを回すだけなので、
**勢力が5つに増えても時計側は1行も変えなくてよい。**

### 8-2. 略奪

**交戦中に「相手勢力の拠点の金ブロック」を押した時だけ**、預金ではなく略奪になる。
自勢力の銀行は交戦中も今までどおり預金として動く。

| 項目 | 値 |
|---|---|
| 1回 | **金30 + 石油2** |
| 間隔 | **10秒**（押した本人ごと） |
| 上限（1戦争・1勢力あたり） | **金300 / 石油10** |

- **石油は5回で打ち止め**（上限10 ÷ 1回2本）。回数を数える仕組みは要らない
- 双方向。宣戦された側も相手の銀行を叩ける
- 相手の貯金が0なら、それ以上は動かない
- **傭兵は略奪できない**（預金もできない）
- 動くたびに全体通知（表示の作り込みはプラグインの担当）

**石油は個人スコア**なので、勢力の合計からは引けない
（`sekiyu_gokei` は毎秒作り直される派生値で、引いても1秒で戻る）。
**相手勢力で最も多く持っている個人から奪い、押した本人が受け取る。**
腐敗と同じ考え方で、溜め込んでいる人が狙われる。

拠点の見分けは、施設マーカーに付けた `jidai_kyoten_<チーム名>` の印で行う。
**印は summon と同時に付ける。** 置いたあとで `tag` を足す形にしたら、
チャンクの読み込みが間に合わず印の付かない拠点が出た（実測）。

### 8-3. 占領

**交戦が終わった時点で貯金が0で、かつ相手が一度は略奪していれば占領される。**

条件は2つ。**両方そろって初めて占領が成立する。**

| 条件 | なぜ要るか |
|---|---|
| 貯金が0 | 「尽きた」ことの目印 |
| **相手が一度は略奪している** | これが無いと、時代進行で貯金を使った直後に、**指一本触れていない相手から占領される**。最も前進した勢力が最も惨めになるので、「殴った者だけが取れる」形にした |

- **不利益は無い**（貢納も制限も付けない）。状態と表示だけ
- サイドバーに `[占領]` と出る
- **時間では解けない。** 解除は下剋上の行使だけ
- 両方が奪い合って両方0になった時だけ、**互いに占領し合う**形になる
- すでに占領されている勢力がまた占領されると、後から占領した側で上書きされる
- 貯金は0でも相手が一度も略奪していない時は、**その旨を全体に知らせて占領しない**

### 8-4. 下剋上

**販売所の商品。** 戦争の結果とは別の、独立した手段。

| | |
|---|---|
| 買う | 誰でも（勢力の正規メンバー）。占領されていなくても買える |
| 値段 | **勢力の金150**。中央が**近代**になると売り出す |
| 保有 | **1勢力につき1つまで** |
| 行使 | **リーダーだけ**（`jidai_leader` タグ）。かつ**自勢力が占領されている時だけ** |
| 効果 | 占領が解ける ＋ 占領していた勢力へ**即時開戦**（準備なし・略奪の上限2倍）＋ 権利を消費 |

**再戦禁止（30分）も無視して開戦できる。** 占領から抜ける唯一の手段なので、
ここで止めると詰んでしまう。

解禁を**中央の時代**で見るのは、銃の解禁や最低雇用料と揃えるため。
勢力の時代で見ると、遅れている勢力（＝占領されがちな側）ほど買えなくなる。

### 8-5. 傭兵の分離（v6 で直したこと）

**契約中の傭兵が勢力の金を使えてしまっていた。**
`kinko_yomu` と勢力の販売所がチームだけで判定していたため、
雇い主のチームに入った傭兵が金庫を読めていた。

v6 では次のようにした。

| | |
|---|---|
| 未雇用の傭兵 | **`youhei` チーム**に入る（データパックが毎秒 入れる） |
| 契約中の傭兵 | 雇い主のチーム（プラグインが移す）。**`youhei` は 1 のまま** |
| 勢力の貯金 | **`youhei=1` は読めないし書けない**（チームに関係なく） |
| 銀行 | 傭兵は預金も略奪もできない |
| 個人の金の販売所 | **傭兵も今までどおり使える** |

**チーム所属は「味方かどうか」、`youhei` は「勢力の正規メンバーかどうか」。**
傭兵を常に専用チームへ隔離すると、PvP の味方判定が壊れるので、
分離は `youhei` スコアで行っている。

# 第2部 マップ骨格 `map/` ── 800版と1500版

**1500版で確定。** 実機計測の結果、拠点距離 r=410 はそのまま採用する。

| 計測項目 | 実測 | 判断 |

## 3-5. 傭兵 ── チーム所属と集計対象の分離（最重要）

### 識別方法: **専用のスコア `youhei`（1=傭兵）を使った**

「チーム未所属で判定」は**採用しなかった**。理由は指示書 2-3 のとおりで、
**契約中の傭兵はプラグインによって雇い主のチームに入る**ため、
チームだけで判定すると傭兵の石油が勢力の合計に混ざり、
時代進行の条件A（石油20%）が狂うからである。

| 状態 | チーム | `youhei` | 合計に入るか |
|---|---|---|---|
| 勢力の正規メンバー | 所属あり | 0 | **入る** |
| 未雇用の傭兵 | 無所属 | 1 | 入らない |
| **契約中の傭兵** | **雇い主のチーム** | **1 のまま** | **入らない** |

### 分離のしかた

```
execute as @a[team=kyuryo,scores={youhei=0}] run scoreboard players operation 丘陵 sekiyu_gokei += @s sekiyu
```

- **チーム所属** = 味方かどうか（プラグインが出し入れする）
- **`youhei`** = 勢力の正規メンバーかどうか（集計はこちらで判定）

**プラグインは契約でチームに入れても `youhei` を 0 に戻さないこと。**
戻すと条件Aが狂う。SCOREBOARD.md に明記した。

### 実測（対照実験つき）

| 検証 | 結果 |
|---|---|
| 無所属の傭兵は合計に入らない | 正規12本 + 傭兵99本 → **合計12** |
| **契約中（雇い主のチームに居る）傭兵も入らない** | **合計12のまま** |
| 対照: チームだけで数えると | **111**（＝混ざる。だから分離が要る） |

**対照実験を入れたのは、分離が効いているのか、たまたま条件が揃っただけなのかを
区別するため。** チーム基準だと本当に111になることを示している。

### なぜスコアにしたか（タグではなく）

指示書が「プラグインはスコアボードを読み書きする」としているので、
**契約の状態をスコアで持つ方が境界が1本に揃う。**
セレクタでも `scores={youhei=0}` としてそのまま使える。

ただし**枠が無い人は `scores={youhei=0}` に一致しない**ので、
`clock` の先頭で全員に `add @s youhei 0` して枠を作ってから集計している。

## 3-10. 4割徴収の端数処理

**切り捨て。** 整数の割り算なので、持っている側が少し得をする。

**実物のストラクチャーに差し替える時も、上の5つを守れば
`fill` を `place structure` に置き換えるだけで済む。**
footprint 12×12 なら高さ32まで1つのストラクチャーに収まる（上限32×32×32）。
それを超える段階だけ縦に分割する。

#### 実測

| 検証 | 結果 |
|---|---|
| 時代1→4 で外観が変わる | 丸石3段 → ネザーレンガ22段。前の段階は残らない |
| **周囲は切替後も空気** | 出口4方向と待機位置すべて空気（**埋まらない**） |
| 土台は詰まっている | Y97/98 が空気でない＝中に立てない |
| 横に広がらない | footprint の外（X=6）は空気のまま |
| 石油の落下位置 | footprint 内に**0本**。4方向の出口すべてに散らばる |

建築物の実物は別工程。今は仮ブロックで段階が変わることまで。

## 3-16. 先行ペナルティと腐敗の報告（v5）

指示書「先行ペナルティと石油の腐敗」§11 で聞かれた項目への回答。

### 先行の定義 ── 推奨案を採ったが、対象は「2勢力」ではなく「1勢力」

推奨どおり **勢力の時代 > 中央の時代** にした。ただし指示書の理由づけ
「中央は2勢力到達で進むので、先頭2勢力が自動的に対象になる」は**成立しない**。

`shinko/chuo` は `shounin_*` の最後から**即座に**呼ばれるので、
2つめの勢力が到達した瞬間に中央も上がり、両方とも先行でなくなる。
**2つめの勢力が先行でいる時間はほぼ0秒。**

実測（`[12-E]`）:

| 場面 | 丘陵 | 森林 | 中央 |
|---|---|---|---|
| 丘陵が時代2を承認した直後 | **先行** | — | 1 |
| 森林が時代2を承認した直後 | — | — | 2 |

目的が「独走を止める」なので、**独走中の1勢力だけが対象**になるのはむしろ都合がよい。
作成者に確認してこの形で確定した。

### 位置公開の実装と負荷

**発光（`effect give ... minecraft:glowing infinite 0 true`）を選んだ。**

| 理由 | |
|---|---|
| 実装が単純 | コマンド1行。座標計算も地図も要らない |
| チームの色で光る | どの勢力かが同時に分かる。**数字を読ませない** |
| 遠くからでも分かる | 地形を透過するので地下に隠れても見える（＝隠れられないペナルティ） |

**負荷: 1秒あたり最大10コマンド前後。** 先行になるのは常に1勢力だけなので、
50人でも光るのは1勢力ぶん（10人程度）。毎秒かけ直しても
**効果は1つのまま**（実測）なので、重ねがけの心配もない。

「かけ直す」形にしたのは、**ログアウトからの復帰に対応するため**。
効果はログアウトしても死んでも残るので、消す側は `jidai_hikari` タグで
「こちらが光らせた人」を覚えておき、対象から外れた人だけを消している。

### 採取コスト増の実装と実測

**案A（拾っても一定確率で1本にならない）。**

```
失う本数 = 拾った本数 × ロス率 ÷ 100 （切り捨て）
          + 切り捨てた端数の割合で、確率的にもう1本
```

端数を確率で埋めているのが要点。**中央では石油が1本ずつ湧く**ので、
切り捨てだけだと「1本ずつ拾えばペナルティを完全に回避できる」ことになってしまう。

確率は `random value 1..100`（1.20.2+ にある。1.21.10 で実測）で作った。
**倍率が `先行_ロス率` で調整できる**のはこの命令のおかげ。
ルートテーブルの `random_chance` だと確率がJSONに焼き付いて調整できない。

実測（`tests/verify_jidai.py` `[12-E]`。`senkou/loss` を直接呼んで数えた）:

| 条件 | 期待 | 実測 |
|---|---|---|
| ロス率 0%・1本×20回（対照） | 0本 | **0本** |
| ロス率 100%・1本×20回（対照） | 20本 | **20本** |
| ロス率 50%・4本まとめて×20回 | 40本（毎回きっちり2本） | **40本** |
| ロス率 50%・1本ずつ×200回 | 約100本 | **90本** |

**対象は中央プラント産の石油だけ**（`moto:"chuo"` の印）。
全部の拾得を対象にすると、**引き出して拾い直しただけで半分失う**ことになり、
取引そのものが成立しなくなる。

### 腐敗の減り方と傭兵への影響

**割合（10%）・切り上げ。** 猶予だけ傭兵を別設定にした（勢力15分 / 傭兵30分）。

| 選択 | 理由 |
|---|---|
| 固定本数ではなく割合 | 勢力は50〜100本、傭兵は数本。固定だと傭兵への痛みが大きすぎる |
| 切り捨てではなく切り上げ | 切り捨てだと少量が0本になり「傭兵に小分けして預ければ腐らない」抜け穴が復活する |
| 傭兵の猶予は2倍 | 割合で痛みは揃うが、傭兵は補充手段が「雇われる」しかないので時間で緩める |

実測: 20本の傭兵 → 2本腐る → 使えば腐らない → 使わずに猶予を過ぎるとまた腐る。

### 引き出し中の石油を総量に含める実装

`fuhai/mochi` が `clear @s <石油> 0`（**1個も消さずに個数だけ返す**）で
手持ちを数え、勢力の総量に足している。

**含めないと、腐る直前に全部引き出して逃げられる。**

> **この経路だけは実サーバー検証で通せていない。** `clear` はプレイヤー専用で、
> 検証で使っているアーマースタンドでは動かない。書いてあることの確認までしか
> できていない（`[12-F]`）。**実機で1回確かめること。**

### オフラインのプレイヤーの扱い

**世代番号方式は「適用」には使えるが、「検知」には使えない。**

| | 使えるか |
|---|---|
| 徴収のように「1人1回だけ適用する」 | **使える**（v4 の `choshu` がそれ） |
| 腐敗のように「総量が減ったかを見る」 | **使えない** |

腐敗が見ている `sekiyu_gokei` は `@a`（＝**オンラインの人だけ**）で作られている。
そのため **誰かがログアウトすると総量が減り、腐敗の時計が戻る。**
「落ちれば腐らない」が成立してしまう。

塞ぐなら「支払いイベント検知式」（引き出した石油に勢力の印を付け、
別勢力・傭兵が拾った時点で支払いと認める）になるが、関数が3つほど増える。
**今回は単純方式のままにして、抜け道として明記する**ことで作成者と合意した。

なお **`条件A`（石油20%）も同じ性質を持っている**（v4 から）。
落ちている人の石油は進行条件に数えられない。上の対策を入れると一緒に直る。

### 腐敗で進行条件を下回った場合

**承認は通らなくなる。** `shinko/shounin_*` は承認の時点で3条件を
もう一度確かめるので、腐敗で20%を割っていれば「条件を満たしていない」と断られる。

**すでに承認済みの時代は戻らない。** 腐敗は保有量を減らすだけで、
時代そのものには触れない。

### サイドバーの行数

**変わらない。5勢力で12行のまま**（15行の上限内）。

先行の表示行は**足していない**。発光そのものが表示なので、
サイドバーに「先行:1」のような数字を出すと、KUN の指摘（数字を読ませない）に反する。
プラグインが独自に出したい場合のために、`senkou` スコアは読める形にしてある。

## 3-17. 戦争・略奪・占領の報告（v6）

### 指示書の検証項目

すべて `tests/verify_jidai.py` の `[12-G]` `[12-H]` `[12-I]` で実測している。

| 項目 | 結果 |
|---|---|
| 準備中は略奪できない | **PASS**（相手の貯金 500 のまま） |
| 上限に達したら、押しても移動しない | **PASS**（金300で 0、石油10で 0） |
| 石油は5回で打ち止め、金は10回まで動く | **PASS**（数えて 5回 / 10回） |
| 自勢力の銀行は交戦中も預金として動く | **PASS**（130→140） |
| 傭兵が押しても何も起きない | **PASS**（略奪も預金も動かない） |
| 貯金0で終了した勢力に占領がつく | **PASS**（`senryou` = 相手の番号） |
| 30分以内の再戦を拒否する | **PASS**（状態3のまま宣戦が通らない） |

### 「石油は勢力スコアか個人スコアか」への回答

**個人スコア。勢力の合計から引くことはできない。**

`sekiyu_gokei` は `jidai:clock` が**毎秒 作り直している派生値**なので、
そこから引いても1秒後には元に戻る。

そこで **相手勢力で最も多く持っている個人から奪い、押した本人が受け取る**形にした
（作成者と確認済み）。腐敗と同じ考え方で、溜め込んでいる人が狙われる。

**制約: オンラインの人からしか奪えない**（`@a` はオンラインのみ）。
相手勢力が全員落ちていると、石油は0本。金は勢力スコアなので奪える。

### 勢力が増えても変わらない部分

**戦争の時計と略奪の本体は、5勢力化しても1行も変えなくてよい。**

| 仕掛け | 効果 |
|---|---|
| 戦争1つ＝マーカー1体 | 時計は `@e[tag=jidai_sensou]` を回すだけ。組み合わせの数だけ行を書かずに済む |
| 相手を**番号**(`bangou`)で指定 | `if score @s bangou = #aite_no` の1行で「相手勢力の人」を選べる。マクロが要らない |

勢力を増やす時に触るのは、勢力名を並べている場所だけ（[HANDOVER.md](HANDOVER.md) §6 に一覧がある）。

### まだ実測できていないこと

**サイドバーの見た目。** 表示名に数字を書き込む形にしたので、
**コマンドが通ることと、並び順のスコアが正しいことまでしか確かめていない。**
実際の見え方はヘッドレスのサーバーでは見えないので、実機で1回見てほしい。

```
/function jidai:hyouji/kousin
```

期待している形:

```
丘陵 石油12 金380
森林[占領] 石油8 金150
中央の時代                3
傭兵の数                  4
```
