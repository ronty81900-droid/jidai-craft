## 1. これは何か

**50人規模の Minecraft イベント企画。** 5つの勢力が中央の石油を奪い合い、
鉄器 → 中世 → 近代 → 現代 と時代を進める。いちばん早く現代に着いた勢力が勝ち。

構成は4つ。**どれか1つだけ直しても動かない**ので、必ず対応関係を確かめる。

| 部品 | 場所 | 役目 |
|---|---|---|
| **Bukkit プラグイン** | `plugin/` | GUI（販売所・ガチャ・銀行 等）・買い物・運営コマンド |
| **データパック** | `datapacks/jidai_craft/` | 状態と判定（時代・戦争・石油・占領） |
| **マップ** | `map/` | 地形と拠点 |
| **リソースパック** | `resourcepack/` | チェスト画面の見た目。**UI の本命ではなくなりました**（下の §6-A） |
| **クライアント MOD** | `clientmod/` | **買い物画面を自分で描く。UI はこちらへ移しました**（下の §6-A） |
| 実機サーバー | `jikki_mod/` | Arclight。**これを起動する** |
| Paper 版 | `jikki_1201/` | MOD 無しの控え |

**プラグインとデータパックの取り決めの正本は `datapacks/CONTRACT.md`。**
どちらを直す時も、先にここを読む。片方だけ変えると黙って壊れる。

## 2. ★★ 作法（このプロジェクトの決まり） ★★

**この4つは、ユーザーからの明示の指示です。守ること。**

### 作法1 ── 記憶で書かない
API も版もコマンドも定数も、**実物を開いて確かめてから書く**。
jar を開く、javadoc を読む、サーバーに打つ。
**そして「どうやって確かめたか」を必ず報告に書く。**

### 作法2 ── 実物で検証する
「コンパイルが通った」で止めない。
**測れないものは「測れない」と正直に言う。** 測ったふりをしない。

### 作法3 ── 読める形で書く
- クラスとメソッドに日本語のコメント。**なぜそうしたか**を書く
- ファイル数を最小に
- **デザインパターンを使わない**
- **依存を足さない**
- 「**動くことより、読めることを優先する**」

### 作法4 ── 範囲を広げない
頼まれていないことを足さない。気付いたことは「範囲外の気付き」として報告する。

### 報告の型（毎回この順で）
1. 確かめた事実と、その確かめ方
2. 検証の結果（件数で）
3. 判断したこととその理由
4. 必要な Java の知識
5. 踏んだ罠
6. 範囲外で気付いたこと

### 既存のものの扱い
**「75点以下なら直す。90点以上ならそのまま採用」。**
自分で採点して、直したもの・そのまま採ったものを一覧で出す。

### 言葉づかい
敬体。**結論を先に**。へりくだらない。
**指示書の前提が間違っていたら、そう言う。** 黙って合わせない。

### ★★ 2026-08-22: クラッシュの真因と、ガチャの作り直し（v0.29.0）★★

#### ★★ クラッシュ `NoClassDefFoundError: SokuteiGamen$Kekka` の真因 ★★

**遊んでいる最中に jar を差し替えたから。**（15:57:17 に差し替え → 15:58:30 に落ちた）

Forge は起動時に jar の目次（どの class がどこにあるか）を覚える。
中身を入れ替えると目次が実物とずれるが、**既に読んだ class は平気**なので、
差し替えた直後は何ごともなく動いて見える。
**まだ一度も読んでいない class** を読む場面に入って、そこで初めて落ちる。
これが「入れ替えてしばらく遊んでから、急に落ちる」の正体。

**対策2つ:**

1. **`haichi.py` が Minecraft の起動中は入れない**ようにした
   （`Get-CimInstance Win32_Process` で javaw/java を見る。`--muri` で押し切れる）。
2. **`mod_kakunin.py` が「組んだ class が1本残らず jar に入っているか」を見る**。
   詰め残しでも まったく同じ落ち方をし、しかも**その class を初めて読むまで
   気づけない**。入れ子の class（`$` つき）はうっかり弾きやすい。
