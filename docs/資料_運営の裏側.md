### 1-2. `/jidai game` ── 運営のゲーム操作（`Kanri.java`）

2語目の語は `Kanri.KOTOBA` の **8 語**: `start` `stop` `reset` `tp` `risu` `spawn` `kyoten` `beacon`。有効な書式は **14 通り**（下の表のうち「3語目なし・不正」と「上記以外の2語目」の2行は使い方を出すだけ）。
**ゲームマスターは開始位置（X=37, Y=175, Z=-938 付近）のコマンドブロックから打つ前提**で、
`Kanri` の処理は **送り手がプレイヤーでなくても動く**ように書いてある。
**足元が要るのは `spawn here` と `kyoten <勢力>` の 2 つだけ。**

| 書式 | 何をするか（実装どおり） | 送り手 | 注意 |
|---|---|---|---|
| `jidai game` | 状態表示。① ゲーム開始中／停止中 ② 石油（停止／稼働 N%／データパック未読込） ③ 初期リスポーン座標 ④ 勢力のリスポーン=拠点 有効／無効 ⑤ 傭兵のリスポーン=プラント周り 有効／無効 ⑥ 石油プラントの座標 ⑦ 拠点の立ち位置の一覧。最後に使い方 | 誰でも | プラントや拠点が「未登録（`/jidai scan`）」と出たら先に `scan` |

## 2. 設定値（`settei`）の一覧

**`load.mcfunction` が置く `settei` の項目は 43 個（うち 2 個はデータパック内部の作業用、1 個はデータパックが毎秒書く派生値）。ほかに廃止済みで `reset` される項目が 3 個ある。**
目的名は `settei`、**保持者の名前がそのまま設定項目名**。

書き方は 4 種類あり、**運営が変えた値が残るかどうかがここで決まる**。

| 書き方 | 意味 | 再読込（`/reload`）でどうなるか |
|---|---|---|
| `scoreboard players add <項目> settei 0` | 無ければ作る・あればそのまま | **残る** |
| `execute unless score <項目> settei matches 1.. run set <値>` | 1 以上が入っていなければ既定値 | 1 以上なら**残る**。**0 にすると既定値へ戻る** |
| `execute unless score <項目> settei matches 0.. run set <値>` | スコアがまだ無い時だけ既定値 | **0 を含めて残る**（0 が意味のある値だから、この書き方になっている） |
| `scoreboard players set <項目> settei <値>`（条件なし） | **毎回 上書き** | **必ず既定値へ戻る** |

### 2-1. 運営が手で動かす 2 つ（**プラグインが書いてよい唯一の `settei`**）

| 項目 | 既定値 | 書き方 | 意味 | 変えるとどうなるか |
|---|---|---|---|---|
| `石油_停止` | **0** | `add 0` | 1 なら中央プラントが1本も出さない | `jidai sekiyu tomeru` / `hajimeru`、`jidai game start` / `stop`、`reset zenbu` が書く。1 の間は `clock` が `#plant_t` を 0 に戻すので、**再開時にまとめて湧かない** |
| `石油_倍率` | **100** | `unless matches 1..` | 湧く速さの百分率。100 が通常、50 で半分 | `jidai sekiyu osaeru <1〜100>` が書く。`clock` は `石油_間隔秒 *= 100` してから `/= 石油_倍率`（先に割ると整数で 0 になる）。**0 だと割り算が黙って捨てられるので `load` が 1 以上を保証している** |

### 2-2. 石油の湧き

| 項目 | 既定値 | 書き方 | 意味 | 変えるとどうなるか |
|---|---|---|---|---|
| `石油_上限_鉄器` | 750 | `unless 1..` | その中央時代に湧く**総本数** | 総量 × 間隔 = 湧き切るまでの秒数（鉄器 750×5=3750秒=62分）。1勢力ぶん×5勢力より多く出す設計。減らすと中央が早く枯れる |
| `石油_上限_中世` | 1800 | `unless 1..` | 同上（1800×3=5400秒=90分） | |
| `石油_上限_近代` | 3350 | `unless 1..` | 同上（3350×2=6700秒=112分） | |
| `石油_上限_現代` | 3350 | `unless 1..` | 同上 | |
| `石油_間隔_鉄器` | **10** | **条件なし `set`** | 中央プラントが1本落とす間隔（秒）。**1か所あたりの秒数**（2026-08-20 に変更。1回の湧きで4か所すべてに1本ずつ落ちる） | 小さくすると石油が速く湧く。**`load` を打ち直すと必ず 10 に戻る**。遊んでいる最中の調整は `jidai sekiyu osaeru` で行うこと |
| `石油_間隔_中世` | **10** | 条件なし `set` | 同上 | 同上 |
| `石油_間隔_近代` | **10** | 条件なし `set` | 同上 | 同上 |
| `石油_間隔_現代` | **10** | 条件なし `set` | 同上 | 同上 |
| `石油_時代上限` | 0 | `add 0` | **作業用の入れ物**。`jidai:clock` が毎秒 `石油_上限_<時代>` をここへ写す | **直すのは時代別の方**。ここを書いても毎秒 上書きされる |

### 2-3. 時代進行の3条件（**その勢力の今の時代**で切り替わる）

## 4. プラグインとデータパックの境目（`datapacks/CONTRACT.md` の要点）

**取り決めの要点は 7 つ。**

> **プラグインが読むのはこのファイル（CONTRACT.md）だけ。ここに書いていない名前は使わない。**
> 名前を変えたら、同じコミットで CONTRACT.md も直す。長い解説は `docs/SCOREBOARD.md` だが、**食い違ったら CONTRACT.md が正**。

### (1) 分担

| | 持つもの |
|---|---|
| **データパック** | スコアの定義・戦争の状態機械・略奪・占領・時代進行・腐敗・サイドバー・**全体通知** |
| **プラグイン** | 右クリック検知（**4施設すべて**）・GUI・購入手続き・傭兵の契約・リーダーの指名・`jidai_leader` タグ |

**プラグインは目的（objective）を1つも新規に作らない。**

### (2) プラグインが書いてよいスコア

`chokin` / `kane_kojin` / `sekiyu` / `youhei` の 4 つ。

### (3) 書いてはいけないスコア

- `sensou` / `sensou_aite` / `sensou_byou` … **毎秒作り直される派生値**
- `sekiyu_gokei` … 同上
- `senryou` / `gekokujo` … 占領と権利はデータパックが決める（**金も引かない＝引くと二重取り**）
- `bangou` / `jidai` / `chuo` … データパックの持ち物
- `settei` … 下の例外2つ以外
- **戦争のマーカーのスコア全部**（`w_kuni` `w_aite` `ryakudatsu_*_a/_b` `sensou_bai`）。**マーカー自体を読まない**

### (4) 例外① 石油の栓（2026-08-20 追加）

`settei` の **`石油_停止` と `石油_倍率` の 2 つだけ**はプラグインが書く。
**なぜ例外にしてよいか**: データパックはこの2つを `scoreboard players add … 0`（無ければ作る・あればそのまま）で置いており、**毎秒 上書きしない**から。
他の `settei` は `execute unless … matches 1..` で初期値を決めるだけなので、**プラグインが書いても読み込み直しで戻ってしまう**。

### (5) 例外② 運営のリセットと制圧（2026-08-22 追加）

| いつ | 何を書くか | なぜ許すか |
|---|---|---|
| `jidai game reset` | `chuo`(世界)=1 / `jidai`(各勢力)=1 / `wakidashi`(世界)=0 | 運営が企画を最初に戻す操作。**データパックには「戻す」関数が無い** |
| `jidai game reset zenbu` | 上に加えて `chokin` `senryou` `gekokujo` `shokuminchi` `senkou`(各勢力)=0 / `shouri`(世界)=0 / `kane_kojin` `sekiyu`（**持っている人だけ**）=0 / `jidai_sensou` のマーカーを `kill` → `jidai:sensou/youyaku` | 同上。戦争はマーカー1体＝1件なので消すしかない |
| 制圧（ビーコンを落とした） | `jidai:sensou/shokuminchi` のあと、**その2勢力の戦争マーカー**（`tag=w_<a>,tag=w_<b>`）に `sensou=3` / `sensou_byou=戦争_禁止秒` を書き、`jidai:sensou/youyaku` | 「制圧＝終戦」にするため。**読むのではなく、番号のタグで選んで命令で書くだけ**。要約は直後に作り直させる |

- **`choshu`（徴収の世代）には触らない。** 戻すと全員が未徴収扱いになり、石油を4割 取られる。`KanriTest` が見張る。

### (6) プラグインが呼ぶ関数（3 個）と、その約束

**`@s` を見る関数は、必ず `execute as <名前> at <名前> run function …` で本人として走らせる**（参加者に `/function` の権限は与えないので、コンソールから実行する）。
**1.20.1 に関数の引数（マクロ）は無い。** `function … {kuni:"丘陵"}` は `Incorrect argument` で落ちる（実測）。引数は**先にスコアへ置く**。

| 関数 | 誰として | 先に置くスコア |
|---|---|---|
| `jidai:sensou/sensen` | 誰でもよい | `#w_kuni` `#w_aite` `#w_soku`（目的 `sagyou`） |
| `jidai:sensou/gekokujo_kau` | **買う本人** | なし |
| `jidai:sensou/gekokujo_tsukau` | **リーダー本人** | なし |

```
scoreboard players set #w_kuni sagyou 1     ← 宣戦する側の番号
scoreboard players set #w_aite sagyou 2     ← される側の番号
scoreboard players set #w_soku sagyou 0     ← 0=ふつう / 1=即交戦（下剋上専用・略奪上限2倍・再戦禁止を無視）
function jidai:sensou/sensen
```

- **3つとも必ず置くこと。** 前回の値が残っていると別の戦争が始まる
- 番号は `bangou` で引く（`scoreboard players get 丘陵 bangou` → 1）
- 範囲外の番号・自分自身への宣戦・再戦禁止中は**黙って弾かれる**
- **開戦の全体通知・演出はデータパックが出す。プラグインは出さない**

**★ 断られたことは、呼び出し側からは分からない。**
`sensen` は条件に合わないと `return 0` するだけで、**命令そのものは成功したように見える**（実測。1.20.1 に `return fail` は無い）。
だからプラグインは 戦争宣誓 の代金 100 を先に引き、呼んだあとに **`jidai:sensou/youyaku` を呼んでから `sensou` を読み直し、1以上になっていなければ返金**する。
`gekokujo_tsukau` も同じで、`senryou` を読み直して効いたかを判定する。**この「呼んだあとに状態を読み直す」約束を崩さないこと。**

## 5. 運営が踏みやすい罠（★の注意を集めたもの）

**番号を付けた罠は 31 件**（ほかに 5-8 の運用注意 3 件）。出典を各行の末尾に付けた。

### 5-1. 打ち方・打つ場所（5 件）

1. **コマンドブロックにはスラッシュを付けない**（付けても動くが、慣例として付けない）。結果は**コマンドブロックの「前回の出力」**に出る。人数や「未登録」の知らせはそこで読む。― `docs/運営コマンドブロック.md`
2. **足元が要るのは `jidai game spawn here` と `jidai game kyoten <勢力>` の 2 つだけ。** コマンドブロックには足元が無いので、この2つは断られる。― `Kanri.java` 冒頭・`kyoten()`・`spawn()`
3. **`/jidai add` `juki` `gacha` `beacon` `chuo` `remove` の 6 個もゲーム内限定。** コードの分岐が `if (!(sender instanceof Player player))` の門番より**後ろ**にあるため。― `JidaiCraft.jidaiCommand`
4. **`game` が Player 門番より前にあること自体を `KanriTest` が見張っている。** 順番を入れ替えるとコマンドブロックから弾かれる。― `docs/運営コマンドブロック.md` 第5節

### 5-2. リセットが触るもの・触らないもの（5 件）

6. **★ `reset` は徴収の世代 `choshu` に触らない。** 世界の値だけ戻すと**全員が「まだ徴収されていない人」と見なされて、石油を4割 取られる**。― `Kanri.reset` / `CONTRACT.md` / `docs/運営コマンドブロック.md`
7. **★ 特殊アイテムの「勢力ごとに各1個」の記録は、`zenbu` でなくても戻る**（2026-08-23 の指示）。時代だけ戻しても記録が残っていると二度目の催しで特殊アイテムが1個も出ないため。**遺物の効果も一緒に切れる。**― `Kanri.reset`
8. **★ `reset zenbu` は現物の紙も取り上げる。** 記録だけ消して紙が手元に残っていると、リセット直後にリーダーが5種そろえたまま＝**即 勝利**になる。― `Kanri.reset` / `Shouri.kaishu`
9. **`reset zenbu` のあとは「停止中」。`jidai game start` を打つまで石油は出ない。**― `Kanri.reset`
10. **`reset` の `zenbu` は完全一致でしか効かない**（`args[2].equals("zenbu")`）。`zenb` のような打ち間違いは**黙って軽い方のリセット**になる。同じく `risu` は 3語目が `youhei` 以外だと**黙って勢力側の `risu`** になる（`tp` だけは 3語目が不正なら使い方を出す）。― `Kanri.command`

### 5-3. 止めても止まらないもの（1 件）

11. **★ `jidai game stop` が止めるのは石油の栓だけ。** データパックの時計（戦争・腐敗・時代判定・サイドバー・所持金の帯）は動き続ける。**時計ごと止めるとサイドバーも帯も止まり、「止めた」のか「壊れた」のか参加者に見分けがつかない**ため、あえてそうしている。戦争や腐敗も止めたいなら `reset zenbu` で戦争を消すか、`settei` で猶予を伸ばす。― `Kanri.kirikae` / `docs/運営コマンドブロック.md` 第4節

### 5-4. 位置・スポーン（6 件）

12. **★ 拠点の座標はソースにもドキュメントにも書いていない。** `/jidai scan` が施設マーカーの `jidai_kyoten_<勢力>` から「施設の並びの2ブロック手前（+z）」を求めて `config.yml` に保存する。**`jidai game` で「未登録」と出たら、先に `/jidai scan`。**― `Kanri.java` 冒頭 / `docs/運営コマンドブロック.md` 第3節
13. **★ 実機で一度 `/jidai scan` を打つこと**（0.31.0 で初めて覚える項目なので、古い `config.yml` には入っていない）。― `次のチャットへ.md`
14. **`/jidai scan` はマーカーが1件も見つからない時、今の登録を消さない。** 「見つからなかった」だけで終わるので、**成功したと勘違いしやすい**。読み込み済みマーカー数と forceload 区画数を必ず読むこと。― `JidaiCraft.jidaiCommand`
15. **★ `jidai game beacon` の「後方」は立ち位置の -z 16 ブロック固定（`BEACON_USHIRO`）。拠点の向きを変えたら、この 16 を見直すこと。**― `Kanri.java`
16. **`/jidai beacon <チーム名>`（足元のビーコンを手登録）と `jidai game beacon`（5拠点の後方にビーコンを建てる）は別のコマンド。** 名前が似ているので取り違えやすい。― `JidaiCraft.jidaiCommand` / `Kanri.beacon`

### 5-5. 設定値（`settei`）（5 件）

18. **★ `石油_間隔_鉄器`〜`_現代` は `unless` を付けずに毎回 上書きしている。** `/reload` や `load` を打ち直すと**必ず 10 に戻る**。遊んでいる最中の調整は **`jidai sekiyu osaeru <1〜100>`** で行うこと。― `load.mcfunction`
20. **★ 先行・腐敗・戦争・略奪・下剋上の設定だけ `matches 0..` で書いてある。** これらは **0 が意味のある値**（ペナルティ無し・即座に腐る）なので、`matches 1..` にすると運営が 0 にしても `/reload` で既定値へ戻ってしまう。**書き方を揃えないこと。**― `load.mcfunction`
21. **★ `石油_倍率` が 0 だと割り算が黙って捨てられる**ので、`load` が 1 以上を保証している。`clock` 側も `石油_間隔秒 *= 100` してから `/= 石油_倍率`（先に割ると整数で 0 になる）。― `CONTRACT.md` / `load.mcfunction`
22. **`docs/SCOREBOARD.md` は「`load` は `set` で書くので再読込のたびに初期値へ戻る。イベント中に変えるなら `load` を打ち直さないでください」と書いている。** 実際に無条件 `set` なのは `石油_間隔_*` の4つで、他は `unless` 付きだが、**イベント中に `/reload` を打たない**という運用は変えないこと。― `docs/SCOREBOARD.md` 第6節

### 5-6. データパックとの境目（5 件）

23. **★ 宣戦（`sensen`）は断られても成功したように見える。** `return 0` するだけで命令自体は成功する（1.20.1 に `return fail` は無い）。**呼んだあとに `jidai:sensou/youyaku` を呼んでから `sensou` を読み直し、1以上でなければ返金**する。`gekokujo_tsukau` も `senryou` を読み直して判定する。― `CONTRACT.md`
