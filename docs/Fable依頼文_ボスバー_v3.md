Minecraft のイベント「時代クラフト」で、画面の上に出す**進捗バー**の絵を作ってください。
既にあるUI（販売所・銀行・ガチャ）と同じ**古地図風**で揃えます。

作業場所は、この企画の置き場の直下（`README.md` がある所）です。

## 1. 何のバーか

参加者60〜70人が5つの勢力に分かれ、鉄器時代から未来を目指します。
このバーは**世界全体が次の時代にどれだけ近いか**を示します。

- **2つの勢力が次の時代の条件を満たすと、世界の時代が上がります**
- バーはその進み具合で伸び、時代が上がると**空に戻ります**
- 満タンは `6`（2勢力 × 3条件）。**動きは7段階**（0〜6）

数字は出しません。**バーの伸びと色だけで、視聴者に世界の状態が伝わる**のが狙いです。

時代が上がる瞬間にバーは空に戻るので、**視聴者が2つの時代の色を同時に見る場面はありません。**
色に求めるのは「溝の中で見えること」と「時代ごとに違う色だと記憶に残ること」です（§6-6 の根拠）。

## 2. 作る画像

### `bar_frame.png` ── 枠（空の状態）

| | |
|---|---|
| 大きさ | **728 × 32 px** |
| 内訳 | 中身が入る「溝」が 720 × 24 px。**上下左右すべて 4px の縁** |
| 背景 | 透過（PNG・アルファ付き） |
| 9分割 | **しない**。固定サイズで1枚そのまま描く |
| 角丸 | 外周は**半径 8**（2論理px）。内側へ1pxごとに半径を1減らし、溝は**半径 4**（1論理px）。角の外は透明。バニラの経験値バーのような両端の丸み |
| 目盛り | 溝の **x mod 120 < 4** の列（各段の切れ目の直後）を `dark` で全高に塗る。バニラの経験値バーの区切りと同じ役割 |

バニラのボスバーは 182×5px しかありません。**横はちょうど4倍**（182×4 = 728）で作ります。
GUI scale 4（1080p の自動設定）では1テクスチャ画素 = 1物理画素になり、拡縮なしで出ます。
溝の 720px は **180 論理px**（バニラの 182 ではない）にあたります。

時代の名前（「世界の時代　近代」）は**バーの上にMinecraftが実行時に描きます**。
枠の中に文字を焼き込まないでください。

### `bar_fill_<時代>.png` ── 中身（4枚）

| ファイル | 時代 | バニラの色 | 色の方向 | palette 名 | 参考値 |
|---|---|---|---|---|---|
| `bar_fill_tekki.png` | 鉄器 | `white` | くすんだ灰白 | `muted` | `#AEB8AE` |
| `bar_fill_chusei.png` | 中世 | `yellow` | 真鍮・古びた金 | `brass` | `#C4934B` |
| `bar_fill_kindai.png` | 近代 | `blue` | 青緑 | `info` | `#4FA1B2` |
| `bar_fill_gendai.png` | 現代 | `purple` | 明るい薄紫 | `era_gendai`（★新規） | `#B9A7D0` |

どれも **720 × 24 px**。**同じ形・同じ大きさで、色だけ違う4枚**にしてください。

- **角丸 半径 4**（溝と同じ形）。各角の (0,0)(1,0)(0,1) の3画素が透明になります
- **目盛り**: 枠と同じ **x mod 120 < 4** の列を `dark` で全高に塗る。満タンで枠の目盛りと重なる位置です

「参考値」は目安です。**manifest.json と食い違ったら manifest が正**です（§0 の停止条件に該当）。

クライアントMODはこの色を見てどの絵を使うか決めます。**対応を勝手に入れ替えないでください。**

★ `era_gendai`（現代 `#B9A7D0`）**だけは既存パレットに無い新色**です。
　 §7 のとおり **manifest.json の `palette` に足し**、スクリプトは他の色と同じく manifest から読みます。
　 スクリプトに16進を書く場所は**ありません**。

## 3. 中身の切り方（ここを外すと作り直しになります）

**左端から `720 × value ÷ max` px だけ切り出して描きます。**
中央から広がる、両端から詰まる、といった作りにはしないでください。

切る位置は7つしかありません。

```
0 / 120 / 240 / 360 / 480 / 600 / 720 px
```

720 ÷ 6 = 120 なので、**どの段階も 120px ちょうどの境目**で切れます。

そのため中身は次の1文を満たしてください。**検査 §6-7 はこの文をそのまま機械にかけます。**

> **fill のどの列 x（0〜719）も、列 (x mod 120) と全画素が一致する。**（角丸で透明になる各角3画素だけは比較から外す）

つまり横方向は「120px 周期の繰り返し」か「全列同じ」のどちらかです。
上下方向のグラデーションや模様は自由です。右端だけ違う飾り（キャップ）は**入れないでください**。切ると消えます。

## 4. 色と作りの決まり

### 色の正本

`manifest.json` の `palette` が正本です。勝手に変えないでください（§7 の追加1件を除く）。

| 役割 | 参考値 | どこに使うか |
|---|---|---|
| `outer` | `#102329` | いちばん外側 |
| `panel` | `#685E45` | 枠の本体 |
| `light` | `#B2A577` | 枠の上と左のハイライト |
| `dark` | `#1B282B` | 枠の下と右の影 |
| `slot` | `#38474A` | 中身が入る前の空の溝 |

### 派生色（ノイズ用）

「紙の繊維ノイズ」を乗せるには基色の濃淡が要ります。palette にはその濃淡が無い前提で、次を許可します。

- 基色1つにつき**派生色は2つまで**。各チャンネルの差は **±24 以内**
- 派生色は**スクリプトが基色から計算**する。16進で直書きしない
- スクリプトは派生色の一覧（基色名・差分・結果の16進）を **`BOSSBAR_SPEC.md` に書き出す**
- 検査 §6-9 は「画像の全色 ⊆ palette ∪ BOSSBAR_SPEC.md の派生色」を見る

### 古地図風とは（このUIでの決まり）

- **羊皮紙のような、少しくすんだ色**。彩度は高くしない
- **1px の硬い縁取り**。ぼかさない
- **紙の繊維のような細かいノイズ**を薄く乗せる。fill に乗せる場合も §3 の1文を守る
- **斜めのハッチングは使わない**（横に切ると縞がずれて見える）
- 角は**外周 半径8・溝 半径4 の角丸**（v3 で変更。画素中心が円の内側なら塗る、アンチエイリアスなし）

### 既存の絵が全部守っている決まり（`manifest.json` の `qa` より）

- アンチエイリアスを掛けない。**中間色を作らない**
- アルファは **0 か 255 だけ**。半透明を作らない
- **完全に透明な画素の RGB は `0,0,0`** にする
- 1枚あたりの色数を抑える。**このバーは32色以内**

## 5. どう作るか

**手で描かないでください。絵を吐くスクリプトを書いてください。**

既存のUIも同じ作り方です（`manifest.json` の `provenance` に
`deterministic raster construction from a fixed palette, integer rectangles,
one-pixel lines, repeated stamps and mirrored coordinates` と書いてあります）。

| | |
|---|---|
| 置き場所 | `clientmod/tools/bar_tsukuru.py` |
| 吐き先 | `clientmod/ui/assets/jidaiui/textures/gui/` |
| 動かし方 | `python clientmod/tools/bar_tsukuru.py` |

守ること。

- **2回動かしたら同じ byte が出る**こと。乱数は `numpy.random.default_rng(固定の種)` を使う
- **フォントを読み込まない。文字を描かない**（名前はMinecraft側が実行時に描く）
- **色は全部 `manifest.json` から読む。スクリプトに16進を書かない**（新色も §7 で manifest に足すので例外なし）
- 派生色は §4 の規則で基色から計算し、`BOSSBAR_SPEC.md` へ書き出す
- プレビュー（§8）も同じ実行の中で吐く

### `BOSSBAR_SPEC.md` に書くこと

これは**クライアントMODのレンダラを書く人が読む契約書**です。

1. 使った palette 色の一覧（名前・16進）
2. 派生色の一覧（基色名・差分・結果の16進）── §4・§6-9 が読む
3. レンダラ契約
   - バニラ色 → ファイルの対応（§2 の表）
   - fill の描画位置は枠の **(4,4)**
   - 切り出し幅 = **`720 × value ÷ max`**（左端から）。max=6 なら 120px 刻み
   - 溝の論理幅は **180**。バニラの 182 を使うと右端が枠にかかる
   - 枠は 9分割しない。728×32 を 182×8 論理px に描く
   - fill はアルファ 0 の画素（角3画素）を描かない。通常の RGBA ブレンドで良い
4. **この指示文の sha256**

```bash
python -c "import hashlib;print(hashlib.sha256(open(r'docs\Fable依頼文_ボスバー_v3.md','rb').read()).hexdigest())"
```

## 12. 決めきれない所

「ここは決めきれていない」と思ったら、**推測で決めずに聞いてください。**
§0 の食い違い（止まる）とは別に、次のような判断は聞いてください。

- 派生色を fill に乗せるか、frame だけにするか（見た目の好み）
