# 時代クラフト プラグイン (JidaiCraft)

> **★ 蛮族と傭兵は 2026-08-26 に止めました（5勢力のバトルに絞るため）。**
> 下の記述のうち傭兵まわりは【止める前の物】です。
> 今の仕組みと戻し方は `docs/蛮族と傭兵（休止中）.md` を見てください。


Paper 1.21.10 用のサーバープラグインです。
エメラルドブロックを右クリックすると購買GUIが開き、
データパック `jidai_craft` の金（`kane_kojin` / `chokin`）で商品を買えます。

**現在の到達点: 第2部（見た目・演出・音）**

登録した座標のエメラルドブロックだけが販売所になり、そのブロックは壊せません。

> **⚠ 更新時の注意**
> 版が `0.9.1` です。**ビーコンの保護が入りました。**
> `testserver\plugins\` に**古い jar を残さないでください。**
> 同じ名前のプラグインが2つあると読み込みに失敗します。（テストサーバー側は削除済み）

## 4. 施設の登録（拠点を作ったあと）

### まず走査する

データパックで拠点を設置したら、**これ1回**で全施設が登録されます。

```
/jidai scan
```

```
[登録] 走査しました: 販売所 1 / 売却所 5 / 銀行 15 / ガチャ 5
  読み取ったマーカー 27 件 / forceload 区画 24 件
```

プラグインはデータパックが置いた**マーカー**を読んでいます。座標を手で打つ必要はありません。

| マーカー | ブロック | 役割 | 押した時の担当 |
|---|---|---|---|
| `jidai_uru_chuo` | エメラルド（中央に1つ） | **販売所（買う）** | **プラグイン** |
| `jidai_uru` | エメラルド（拠点） | 売却所（貴金属を売る） | データパック |
| `jidai_ginko` | 金（拠点に3つ） | 銀行（預ける） | データパック |
| `jidai_gacha` | ダイヤ（拠点） | ガチャ | **プラグイン** |

**4種すべてが「壊せない」保護の対象**です。押した時の処理は、データパックの担当分には
**一切手を出しません**（打ち切ると売却も預金も動かなくなるため）。

### 起動時にも自動で走査します

起動から5秒後に自動で走ります。**ただし0件だった時は、今の登録を消しません。**
マーカーは読み込まれている区画にある分しか取れないためです。0件だった場合はログに警告が出ます。

```
[JidaiCraft] 自動走査: マーカーが1件も見つかりませんでした ...
[JidaiCraft]   登録は消していません（27 件のまま）。拠点が読み込まれてから /jidai scan を打ってください
```

### 確認する

```
/jidai list
```

登録した座標に**そのブロックが無い**場合、`※ ブロックが見当たらない登録が N 件あります` と出ます。

## 5. 手で登録する（例外的な場所）

**登録した座標のエメラルドブロックだけが販売所になります。**
参加者が自分でエメラルドブロックを置いても、ただのブロックのままです。

コマンドは **OP を持っている人だけ**が使えます（`plugin.yml` で `default: op` に指定）。

### 置く

1. 販売所にしたい場所に**エメラルドブロックを置く**
2. **そのブロックの上に立つ**
3. 次を実行する

```
/jidai add
```

```
[販売所] 登録しました: world,10,64,-20 (計 1 件)
```

走査で拾えない場所は、従来どおり手で登録できます。

### ガチャを置く

**ダイヤブロック**の上に立って実行します。

```
/jidai gacha
```

### 外す

登録を外したいブロックの上に立って実行します。販売所でもガチャでも同じです。

```
/jidai remove
```

### 一覧を見る

コンソールからでも実行できます。

```
/jidai list
```

### 仕様

- 登録した座標は `plugins\JidaiCraft\config.yml` に保存され、**再起動しても残ります**
- **登録済みのブロックは壊せません**（壊そうとした人に理由が出ます）
- 世界の名前も一緒に記録するので、**ネザーと現世で同じ座標があっても混同しません**
- 登録を外すと、そのブロックは普通のエメラルドブロックに戻り、壊せるようになります

## 6. 販売所の動作確認（手順つき）

金が0だと何も試せないので、先に金を配ります。サーバーのコンソールか、
OP 権限を持ったプレイヤーのチャットで実行してください。

```
scoreboard players set Ronty8190 kane_kojin 10
```

```
team join kyuryo Ronty8190
```

```
scoreboard players set 丘陵 chokin 100
```

（`Ronty8190` はご自分のプレイヤー名に置き換えてください）

エメラルドブロックを置いて右クリックすると、画面が開きます。

| 枠 | 商品 | アイテム | 値段 | 支払元 | 解禁 |
|---|---|---|---|---|---|
| 0 | 食料 | パン ×3 | 2 | 個人の金 | 鉄器（最初から） |
| 1 | 防具 | 鉄の胸当て | 30 | 勢力の金 | 中世 |
| 2 | **銃** | クロスボウ | **120** | 勢力の金 | 近代 |
| 3 | 戦争宣誓 | 赤い旗 | 60 | 勢力の金 | 近代 |
| 4 | 下剋上 | 白い旗 | 40 | 個人の金 | 中世 |

**値段と解禁時代はすべて仮です。** 変える場所は `Shop.java` の `SHOHIN` 一覧だけです。

> **銃を 120 にした理由**
> データパックの `進行_必要貯金` が 100 でした。銃をそれより高くしておくと、
> 「今 銃を買って戦うか、貯めて次の時代へ進むか」の選択が生まれます。
> 指示書の「銃の値段は高く設定する」をこの根拠で具体化しました。

### 未開放の枠

まだ解禁されていない商品は、**灰色のガラス板**に差し替わり、名前が `??? 未開放` になります。
説明には「中央の時代 近代 で解禁」と出ます。中身は伏せたまま、枠があることだけを見せます。

- 解禁は**中央の時代**で決まり、**全勢力に同時**に起きます
  （データパックが「この時代の装備が全勢力に解禁された」と流すのに合わせています）
- 勢力ごとの時代（`jidai`）ではありません
- 画面は**開くたびに並べ直します**。時代が上がったら、次に開いた人から新しい品揃えになります

### 買えた時

枠0（パン）をクリック — **本人にだけ**返ります。

```
[販売所] パン ×3 を購入 (個人の金 10 → 8)
```

枠1（鉄の胸当て）をクリック — **同じ勢力の全員に**流れます。

```
[販売所] Ronty8190 が 勢力の金 で 鉄の胸当て ×1 を購入 (丘陵 100 → 70)
```

勢力の金は所属している全員が使えるため、誰が使ったか分からないと事故になります。
そのため勢力の中には必ず知らせが出ます。買った本人にも同じ文面が届きます。

> **サーバー全員には流しません。**
> 全体に流すと、他勢力に「何をいくつ買ったか」が筒抜けになるためです。
> （データパック側の暫定UIは `tellraw @a` で全体に流します。方針が違う点に注意してください）

### 買えない時（理由が必ず出ます）

| 状況 | 出るメッセージ |
|---|---|
| 個人の金が足りない | `個人の金が足りません (必要 2 / 所持 1)` |
| 勢力の金が足りない | `勢力の金が足りません (必要 30 / 金庫 29)` |
| 勢力に入っていない | `勢力に入っていないため、勢力の金は使えません` |
| 持ち物がいっぱい | `持ち物がいっぱいです。空けてから買ってください` |
| データパックが無い | `データパックが読み込まれていません` |

**いずれの場合も、金は1も減りません。**

### サイドバーの数字について

購入直後、左側のサイドバーの数字が変わるまで**最大1秒かかります**。
不具合ではありません。サイドバー（`hyouji`）はデータパックの時計が
毎秒詰め直す仕組みで、そこはデータパック側の担当だからです。
プラグインは触っていません。チャットの `10 → 8` が正しい値です。

## 8. ガチャの使い方

**ダイヤブロック**を右クリックすると画面が開き、中央のボタンで1回まわします。

- **個人の金 5** で1回（★仮の値段）
- 出るもの: 食料・消耗品・その時代の小物・**たまに金が返る**
- **出ないもの: 銃・防具・武器・石油。** 勢力の戦力に影響する物は入れていません
  （強い物が出ると、ガチャが最適解になって販売所も時代の解禁も無意味になるため）
- 景品は**中央の時代**で増えます（時代1=植木鉢まで / 中世=本 / 近代=時計 / 現代=レコード）

### 景品と確率（すべて仮）

| 景品 | 重み | 解禁 |
|---|---|---|
| パン ×2 | 30 | 鉄器 |
| 焼き鳥 ×3 | 20 | 鉄器 |
| 松明 ×8 | 15 | 鉄器 |
| 金 10 | 15 | 鉄器 |
| 骨粉 ×6 | 10 | 鉄器 |
| 植木鉢 | 8 | 鉄器 |
| 本 | 8 | 中世 |
| 時計 | 8 | 近代 |
| レコード | 6 | 現代 |
| **金 50 大当たり** | 3 | 鉄器 |

**500回まわした実測: 100000 → 98750**（1回5で2500払い、1250が金で戻る＝約5割還元）。
金を吸い取りすぎると誰も回さなくなるので、実プレイで調整してください。
変える場所は `Gacha.java` の `KEIHIN` 一覧と `NEDAN` だけです。

**演出（横スクロールで流れて止まる）は段階8です。** 今は「押す→結果が出る」だけです。

## 9. 演出と音（第2部）

### ガチャの演出

回すと、アイテムが横に流れて**減速しながら真ん中で止まります**（合計 3.2 秒）。
1コマごとに音が鳴り、止まった時に等級で音が変わります。

| 等級 | 景品 | 止まった時の音 | 追加 |
|---|---|---|---|
| ハズレ | パン・松明・骨粉 | `block.note_block.bass` | なし |
| 小 | 焼き鳥・植木鉢 | `entity.item.pickup` | なし |
| 中 | 本・時計・レコード・金10 | `entity.player.levelup` | 本人のみ |
| **大** | 金50 大当たり | `ui.toast.challenge_complete` | **全体チャット＋花火** |

**全体に流すのは「大」だけ**です。中まで流すと通知が多すぎて、大当たりの価値が下がります。

> **★ 順序を崩さないこと**
> `代金を引く → 抽選 → 演出を見せる → **止まった瞬間に渡す**` の順です（十連も、めくり終えてから渡す。途中で閉じた・切断した人にも必ず渡す）。
> 演出は「もう決まった結果」を見せているだけなので、
> **途中で画面を閉じても、切断しても、サーバーが落ちても、景品は既に手元にあります。**
>
> **画面は1人ずつ別に作っています。** 共有していると、他の人が回した演出が
> 自分の画面でも流れてしまいます。演出中でも、別の人は普通に回せます。

### 通知の書式

視聴者が画面を見て種別を見分けられるよう、記号と色を固定しました。

| 種別 | 表示 | 流れる範囲 |
|---|---|---|
| 購入 | `● [購入]` 灰 | 勢力の中だけ（個人の金なら本人だけ） |
| **戦争宣誓** | `✖ [戦争宣誓]` **濃赤** | **サーバー全員** |
| **下剋上** | `✖ [下剋上]` **濃赤** | **サーバー全員** |
| 大当たり | `★ [大当たり]` 金 | 大のみ全員 |
| 時代 | `■ [時代]` 黄 | 全員 |

**戦争宣誓と下剋上だけ、他とはっきり違う色**にしてあります。事故ではなく戦犯として残すためです。

### 時代が進んだ瞬間

中央の時代が上がると、プラグインが1秒ごとの見回りで気づいて演出します。

- 全員の画面中央に **「時代が進んだ / 中央は 近代 へ」**
- 全サーバーに `entity.ender_dragon.growl`（重い音）
- 中央プラントのまわりにパーティクル（**この瞬間だけ**。常時は出しません）
- **解禁された商品を名指し**：`■ [時代] 販売所に「銃」が入荷しました`

判定そのものはデータパックの担当です。プラグインは変化に気づいて見せるだけです。

### 拠点の可視化

`/jidai scan` を打つと、施設の上に**浮遊テキスト**（種別名）を置きます。

| 施設 | 色 |
|---|---|
| 販売所 | 水色 |
| 売却所 | 緑 |
| 銀行 | 黄 |
| ガチャ | 紫 |

**置いたら終わりで、毎tickの処理はありません。** クライアントが表示するだけなので、
数が増えても TPS に影響しません（常時パーティクルを使わないのはこのためです）。

### ビーコン（目印）

**データパックがビーコンを置いたら**、`/jidai scan` で登録され、プラグインが守ります。

| マーカー | 役割 | ガラスの色 |
|---|---|---|
| `jidai_beacon` | 拠点の目印（5か所） | 勢力色（データパックが決める） |
| `jidai_beacon_chuo` | 中央の目印 | **中央の時代で変わる**（鉄器=白 / 中世=黄 / 近代=橙 / 現代=赤） |

**中央の色はプラグインが塗り替えます。** 時代が進んだ瞬間と `/jidai scan` の時です。
中央プラントの建築とは無関係に動くので、建物が無くても色は変わります。

> **★★ ビーコンの効果は絶対に付きません ★★**
> レベル1でも範囲20の採掘速度上昇が付き、「1分に20個」の経済が崩れます。
> そこで**2重に塞いでいます**。
>
> 1. **ビーコンの右クリックを必ず打ち切る。** 目印のビーコンだけでなく、
>    **参加者が自分で置いたビーコンも**塞ぎます（誰の物でも経済は同じように壊れるため）
> 2. **毎秒の見回りで、選ばれている効果を消す。** コマンドで設定された場合の保険です
>
> **効果が無くてもビーム自体は出ます。** 目印としては何も困りません。

**守る範囲はマーカー1つから11ブロック**です。ビーコン本体・上のガラス・下の鉄ブロック3×3。
土台を1つ抜かれるとビームが消えるので、基盤ごと守っています。範囲の外は普通に壊せます。

### 音のID

## 11. データパックとの分担

指示書の分担どおり、**状態と判定はデータパック、操作画面はプラグイン**です。

| | 持つもの |

| データパック | スコアボードの**定義**、貴金属ドロップ、時代進行、サイドバー表示 |

> ガチャ・販売所と同じ方式に揃えました。

## 13. Java の読み方（このコードに出てくる分だけ）

| 書き方 | 意味 |
|---|---|
| `package jidai;` | このクラスの住所。フォルダ構成と一致させる |
| `import` | 他所のクラスを短い名前で呼ぶ宣言 |
| `extends JavaPlugin` | **継承**。土台にして一部を差し替える。プラグインは必ずこれ |
| `implements Listener` | **資格を名乗る**。`extends` は1つだけ、`implements` は何個でも |
| `implements InventoryHolder` | 「この画面の持ち主は自分だ」と名乗る資格。販売所の判定に使う |
| `final` | これ以上土台にさせない |
| `@Override` | 土台側の同名処理を差し替えた印。打ち間違いを止めてくれる |
| `@EventHandler` | イベントの受け口の印。メソッド名は自由、見られるのは印と引数の型 |
| `registerEvents(this, this)` | イベントの**登録**。名乗るだけでは届かない |
| `record Shohin(...)` | 値を持つだけの型を1行で作る。取り出しは `s.namae()` |
| `instanceof` | 型の確認。うしろに名前を書くとその型で受け取れる |
| `static final` | 1つだけ作って差し替えない（商品一覧・スコアボード名） |
| `String[][]` | 表（行の並び）。`KINKO[0][0]` が1行目の1列目 |
| `null` | 「中身が無い」を表す特別な値。確かめずに使うと落ちる |
| `return;` | その処理をここで打ち切る（データパックの `return fail` と同じ） |
| `Component` | 画面に出す文字の型。素の文字列を渡す書き方は非推奨（実測で確認） |
| `onCommand(...)` | `/jidai` を受け取る場所。**`plugin.yml` の `commands` 欄と両方そろって初めて動く** |
| `args[0]` | コマンドの後ろの言葉。`/jidai add` なら `args[0]` が `"add"` |
| `getConfig()` / `saveConfig()` | 設定ファイルの読み書き。**`set` しただけでは保存されない**。`saveConfig()` まで呼ぶ |
| `ArrayList` | 後から足したり消したりできる並び |
| `CommandSender` | コマンドを打った人。プレイヤーとは限らない（コンソールもある） |
| `Map` / `HashMap` | 「鍵で引ける表」。傭兵の名前で申し出や契約を引いている。1人1件しか持たないので、入れ直すと前のが消える＝**申し出の上書きがこれで実現している** |
| `System.currentTimeMillis()` | 1970年から今までのミリ秒。「終わる時刻」を数値で持ち、毎秒それを過ぎたか比べている |
| `() -> youhei.byoumai()` | 「この処理を後で実行してほしい」の渡し方。今すぐ呼ぶのではなく、処理そのものをサーバーに預けている |
| `runTaskTimer(..., 20L, 20L)` | 20tick(1秒)ごとに繰り返す予約。傭兵の見回りに使っている |
| `try { ... } catch (...) { }` | 失敗するかもしれない処理を試し、失敗したら別の処理をする。数字として読めない入力の受け止めに使っている |
| `split(",")` | 文字列を区切りで分ける。設定ファイルの1行を項目に戻すのに使っている |

### わかりにくい点 1 ──「呼ばない」処理

`onEnable()` も `onRightClick()` も `onShopClick()` も、**自分では呼びません。**
サーバーが呼びます。データパックの `jidai:load` を自分で `/function` しないのと同じです。

### わかりにくい点 2 ── 門番を並べる書き方

条件を入れ子にせず「違ったら `return`」を並べています。
段階4で条件が7つに増えましたが、入れ子にしていないので横に深くなっていません。

### わかりにくい点 3 ── コマンドは2か所に書く

`/jidai` を動かすには**2つ揃える必要があります。**

1. `plugin.yml` の `commands:` 欄 — サーバーに「そんなコマンドがある」と教える
2. `JidaiCraft.java` の `onCommand` — 実際の処理

**片方だけだと動きません。** Java 側だけ書くと「Unknown command」になります。
これはイベントの `registerEvents` と同じ構図です。

### わかりにくい点 4 ── 先に断ってから金を減らす

`Shop.kau()` は、**金を減らす前に**断る条件をすべて確かめます。

```
商品があるか → データパックがあるか → 持ち物に空きがあるか → 残高が足りるか
```

順番に意味があります。**金を減らした後に失敗すると、金だけ消えます。**
特に「持ち物がいっぱい」は先に確かめないと、払ったのに商品が消えます。

## 15. 戦争宣誓・下剋上・リーダー

### 分担（実物のデータパックを読んで合わせたもの）

| | 誰がやるか |
|---|---|
| 宣戦の相手を選ぶ画面 | **プラグイン** |
| 戦争宣誓の代金 100（勢力の金） | **プラグイン** |
| 開戦・準備5分・交戦・略奪・占領・再戦禁止・全体通知 | データパック |
| 下剋上の権利を買う（150・1勢力1つ・近代以降） | **データパック**（プラグインは金を引かない） |
| 下剋上を使う（占領解除・即時開戦・上限2倍・権利の消費） | **データパック** |
| リーダーの指名と `jidai_leader` の目印 | **プラグイン** |

### プラグインがデータパックへ送る命令（この3つだけ）

```
function jidai:sensou/sensen {kuni:"丘陵",aite:"森林",soku:0}
execute as <名前> at <名前> run function jidai:sensou/gekokujo_kau
execute as <名前> at <名前> run function jidai:sensou/gekokujo_tsukau
```

- `soku` は**省略できません**。データパックの `sensen.mcfunction` が `$(soku)` を必ず使うため、
  渡さないと `Failed to instantiate function` で止まります。
- 下剋上の2つは `execute as` で**本人にすり替えて**走らせます。
  向こうが `@s` でチーム・傭兵・リーダーの目印を見ているためです。
  参加者に `/function` の権限は与えません。

### 使い方

1. 運営が `/jidai leader set kyuryo <名前>` でリーダーを決める
   → その瞬間に `jidai_leader` の目印が付きます（入り直した時も付け直します）
2. 誰でも 販売所（中央のエメラルドブロック）→「戦争宣誓」を押す
   → **相手を選ぶ画面**が開きます。選べない相手は灰色で、理由が出ます
3. 相手を押した瞬間に**購入確定**（確認は挟みません）。勢力の金 100 が引かれ、宣戦されます
   - ★ 引いたあと、**本当に戦争が始まったかを読み直して確かめます**。
     データパックは条件に合わないと黙って何もしない（命令は成功に見える）ため、
     読み直さないと「100 取られたのに戦争が始まっていない」事故になります。
     始まっていなければ**代金を戻します**。
4. 「下剋上」を押すと、データパックが 150 を引いて権利を渡します
5. リーダー（か代行）が `/gekokujo` で行使します

### 灰色になる条件

| 条件 | 出る文 |
|---|---|
| 自分の勢力 | 自分の勢力です |
| 傭兵など勢力でない | 勢力ではありません（傭兵には宣戦できません） |
| その相手と戦争中 | その勢力とはもう戦争中です |
| 再戦禁止（`sensou`=3） | 再戦禁止 (あと ○分○秒) |
| 相手が別の勢力と戦争中 | すでに戦争中です |
| **自勢力が戦争中** | 自勢力がすでに戦争中です |

> 最後の1つは指示書に無く、こちらの判断で足しました。
> 戦争中に宣戦しても意味が無く、100 を捨てるだけになるためです。
> 要らなければ `Seiryoku.senseniDekiruka()` のその1文を消すだけで戻せます。
